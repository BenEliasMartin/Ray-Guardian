# Manual handoff

Implementation and configuration templates are in the repository. These steps require account owners or physical hardware.

Native verification is available in [the successful GitHub run](https://github.com/BenEliasMartin/Ray-Guardian/actions/runs/43586048755): both iOS builds and all four actual MockDeviceKit Simulator tests passed. Those tests use real SDK media with explicitly labeled provider fixtures. Credentialed provider and telephone checks below still need to run against the configured accounts.

1. Add working Verda and ElevenLabs credentials to ignored `.env`. Confirm the endpoint/model and ElevenLabs voice/model access. Bootstrap has already created local encryption, signing and client secrets; keep them out of chat/git. Run `node scripts/doctor.mjs --require-ready`.
2. On a Mac with Xcode 26.4+ and Swift 6.3+, open the shared RayGuardian project, set an Apple signing team and unique bundle ID if needed, and run Debug. Enter the backend URL/client token in Setup or the ignored Debug xcconfig. The implementation host has no iOS SDK; GitHub CI builds the native app with the pinned SDK and exercises its real MockDeviceKit flow in Simulator. Physical signing and hardware execution still require this setup.
3. For real glasses, enable Meta Developer Mode or configure the app/release channel with the correct Meta application credentials and URL callback. Enable the camera/audio/motion/speech capabilities available to the account. Pair the glasses in Meta AI and explicitly grant camera/microphone permissions. Grant optional phone microphone/on-device speech/location permissions during setup.
4. Prepare the replay files with `scripts/prepare_demo_media.py` if using a fresh checkout. The files are intentionally excluded from git. Use bundled files or fetch/download through Mock glasses. Twelve development clips with original audio are already prepared on the implementation host. For indicator-only privacy behavior, disable automatic scene checks, pre-trigger frames and ElevenLabs listening, and use replay or real glasses instead of the live mock-camera preview.
5. For actual telephone demonstrations, configure a Twilio originating number, an allowlisted ordinary test destination, outbound permissions/verification, and public HTTPS with working DNS. Set the exact `PUBLIC_BASE_URL`. Use a second phone to receive the call. No emergency dispatch integration is installed or implied.
6. Run the credentialed `smoke_guardian.mjs` and production `evaluate_guardian.mjs --live --audio` commands in the README. Check the reported source is Nemotron, STT source is ElevenLabs Scribe, and downloaded MP3 is genuinely returned by ElevenLabs. Ordinary/uncertain results must remain ordinary/uncertain.
7. On iPhone, rehearse: genuine fall and ordinary replay; keyword cancellation; deliberate SOS; absent camera/audio capability; denied permission; glasses removal; thermal fault; backend offline; leaving/locking the app during capture and inference; cancellation while a test phone is ringing; operator DTMF acknowledgment. Check Bluetooth voice routing and actual eight-second startup/capture timing on the chosen hardware.

The software does not establish validated emergency sensitivity/specificity or production background coverage. Human adjudication of cropped validation clips, additional wearer-POV assault/ordinary datasets with permission, calibrated thresholds, platform publishing approval and independent operational validation remain separate from implementation.
